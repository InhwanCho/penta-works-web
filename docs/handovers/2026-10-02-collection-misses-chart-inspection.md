# 연속 수집 누락 및 그래프 측정값 확인

## 변경
- V23: 병원 정책에 collection_interval_minutes(기본 10), missing_collection_threshold(기본 2) 추가.
- 마지막 수집 이후 floor(지연분 / 주기분)으로 연속 누락 횟수 계산. 10분 주기이면 지연 19분=1회, 20분=2회. 최근 1시간 건수와 독립적.
- 이전 기본 30분 기준은 10분/2회로 변경. 별도 설정한 다른 분 기준은 10분 슬롯으로 올림하여 보존. 알림 활성화 여부는 바꾸지 않음.
- 최신 수집 이력이 없는 경우 횟수를 발명하지 않고 null/수집 기록 없음으로 표시. 기존 미수신 알림 경로로 처리.
- 재수집 시 누락 횟수는 0. 열린 NO_DATA 사건은 정상 종료(복구 발송 없음). 반복·수신처·개별 확인완료·SMS 대체 경로 재사용.
- 알림 관리 상세에서 주기/누락 회수/사용 여부를 설정. 총 대기시간 실시간 표시. 최소 주기 5분, 총 대기 최대 1440분.
- noDataMinutes는 주기×누락기준의 호환용 파생 필드. 이전 클라이언트의 분 기준 요청도 수집 슬롯으로 환산.
- 대시보드 전체표 행 강조 + 병원명 옆 누락 횟수, 요약 카드에도 횟수·강조 표시.
- 상세 그래프 interactive=false가 모든 마우스/터치 이벤트를 끄던 문제 수정. interactive는 확대/이동에만 관여.
- 툴팁 및 하단 값 패널에 소수점 값·전체 측정시각 표시. 클릭/터치 고정, 고정 해제, 방향키/Escape 지원. 값 패널 아래 배치로 hover 시 그래프 위치 흔들림 방지.

## 검증
- Java 17 전체 테스트, frontend lint/typecheck/production build.
- 경계(9/10/19/20분), 사용자 주기, 미수집·미래 시각, 입력 범위/오버플로, 사건 생성·재수집 종료 테스트 추가.
- 로컬 전용 API + Chrome 390/820px: 2회 누락 배지·행 배경, 상세 설정 15분/2회→30분 미리보기·저장·재조회 확인.
- 실제 canvas 클릭으로 hepres=3.373 표시·고정, 해제 및 방향키 다른 지점 값 확인.
- 운영 테이블의 작은 검증용 복사본에 V22/V23 성공. 기본 정책 10분/2회 확인. 검증 DB 정리.
- 외부 알림 발송 없음. 운영 DB 마이그레이션·배포·커밋·푸시 없음.

## 배포 시
- 앞선 미배포 컬럼/콜드칠러 변경(V22)과 이번 V23을 함께 배포해야 함.
- 데이터 도착 지연에 대한 별도 유예시간은 추가하지 않음. 마지막 수집 후 20분 경계에서 기본 2회 누락으로 처리하며 감지 스케줄(기본 약 60초)에 따라 실제 발송 시점이 늦어질 수 있음.
