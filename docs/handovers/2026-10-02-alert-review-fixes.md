# 알림 기능·UX 점검 및 수정

## 수정한 문제

1. 조용한 시간/수신처 없음으로 보류된 알림도 마지막 발송 시각을 갱신해, 반복 0(최초 1회)에서는 이후 발송 기회가 사라졌음. 보류는 발송 시각을 보존하고 다음 점검에서 재평가한다.
2. UNKNOWN 상태에서도 자동 반복이 새 배치를 만들 수 있었음. 관리자 수신 확인 전에는 새 자동/수동 배치를 시작하지 않는다.
3. 수신처 목록이 바뀐 상태로 실패 건을 재시도하면 새 배치가 만들어져 성공한 번호에도 중복 발송될 수 있었음. 재시도는 기존 배치를 유지하고 실패 번호 및 새 번호만 시도한다.
4. 정상화로 종료되거나 규칙이 비활성화된 과거 알림을 재전송할 수 있었음. 서버 조회 및 발송 배치 생성에서 차단하고 화면에서도 종료된 알림의 재전송 버튼을 숨긴다.
5. 담당자가 비활성화되거나 병원 권한을 잃어도 수신 번호가 남아 있으면 계속 발송됐음. 발송 시 활성 계정/회사/병원 소속과 일반 사용자 접근 권한을 검증한다.
6. 확인완료 응답이 병원별 최신 500개 중에서만 찾는 방식이어서 오래된 알림은 처리에 실패할 수 있었음. 정확한 사건 ID로 1건만 조회한다.
7. 시작=종료인 조용한 시간은 실제로 아무 시간도 제외하지 않았음. 설정 시 오류로 안내한다.
8. 여러 병원 수신처 등록이 첫 실패에서 중단되고 성공·기존·실패 결과가 불분명했음. 병원별 처리 후 결과를 표시하고 실패 병원만 선택을 유지한다. 다른 담당자/중지 상태의 기존 번호도 명시적으로 알린다.
9. 수신 중지/시작 버튼이 저장하지 않은 전화번호 수정 내용까지 함께 저장했음. 상태 전환은 기존 저장값만 사용하고 편집 재진입 시 저장된 값으로 초기화한다.
10. 이력 필터 변경 뒤 보이지 않는 알림 선택이 확인완료 대상에 남았음. 현재 필터의 진행 중·미확인 사건으로 대상을 제한하고 목록 감소 시 페이지를 유효 범위로 보정한다.
11. 모바일 설정 오류가 긴 스크롤 영역 끝에 있어 보이지 않았음. 고정 저장 영역 위에 표시한다. 사용 중 항목이 없는 병원은 전체 항목으로 시작한다.
12. 단일 확인완료 후 대시보드 미확인 상태가 갱신되지 않았음. 성공 시 대시보드 쿼리를 갱신한다. 새 발송 결과에는 전화번호 끝 4자리를 표시해 수신처를 구분한다.

## 검증

- Java 17: 전체 80개 테스트 통과. UNKNOWN 재발송 차단, 변경된 수신처 재시도, 조용한 시간으로 보류된 최초 1회 알림, 같은 시작/종료 시간 거부 회귀 테스트 추가.
- 프론트엔드 lint, TypeScript, production build 및 git diff --check 통과.
- 외부 발송 없는 로컬 fixture API로 390×844 모바일 화면 확인: 다중 병원 등록 1건 성공/1건 실패 구분, 실패 병원 선택 유지, 문서 가로 넘침 없음, 이력 2페이지의 5건 선택 확인.
- 내장 브라우저가 window.confirm에서 응답하지 않아 확인완료 이후 페이지 보정의 브라우저 종단 검증은 완료하지 못함. 임시 API/개발 서버는 종료함.
- 이번 점검에서 실제 메시지 발송, 공유 DB 변경, 커밋·푸시·운영 배포는 하지 않음. 이전 미커밋 변경은 보존함.
