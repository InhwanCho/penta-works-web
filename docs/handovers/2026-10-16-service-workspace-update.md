# Development service workspace update

User requested continuing development-only deployment, preserving production. Monitoring is restored at `/`, `/monitoring` redirects there preserving query strings, and the former Today page becomes `/overview` (업무 현황). The new overview references the user's Pentaservice dashboard: counters, month calendar/day agenda, next 45 days of PM/ACR, preparation checklist, and recent work. Existing hospital histories are read through the existing Office API; missing legacy ACR kinds are not guessed. Native PM/ACR completed records calculate upcoming dates, respecting explicit hospital overrides.

The profile menu now contains account, authorized administration, appearance preferences and logout. Monitoring is in main navigation and alerts have a separate top-bar button. Global dark anchor-hover colors and workspace links/cards/buttons have explicit dark surfaces/foregrounds.

The work form follows https://wodus654.github.io/20260905pentaservice/: target, type, PM contract/checklist, repair symptoms/parts, Cold Head position/serial/date/helium, ACR subtype/pulse conditions/8 measurement sections, timing, PM inclusion, follow-up and preparation. Fifteen PM checklist rows and ACR field/method definitions and reference diagrams were extracted from the user-referenced repository. ACR arithmetic is retained, while final verdicts require explicit input. Short choices use native radio groups. Hospital selection is a searchable below-field list with keyboard navigation; no native select overlays remain in workspace forms.

V39 adds structured details, company-scoped image storage, hospital plans and preparations. Photo selection, drop, paste, preview, removal and reloading are supported. Input policy: 20 MiB/file, 40 photos, 200 MiB/record; JPEG/PNG/GIF only. Browser corrects orientation while resizing large images to a 2560px long edge. Server checks actual decoding, formats, pixel count, ownership, company/site access, staging quota and attachment atomicity. Normal image bytes retain EXIF; staged uploads expire after a day on the next author upload. Photos are fetched with authentication and no public storage URLs. Existing photo edits commit together with the record, and deleted records cannot expose photos.

Dev Compose keeps all existing outbound notification/sync restrictions and only raises development multipart limits. V39 is not applied to production. No Intranet/production deployment is part of this change.
