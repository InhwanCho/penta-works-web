# 알림 설정·수신처·반복 발송 변경

## 구현

- 대시보드 필터: `알림값 확인`에서 병원별 항목의 적용 범위, 전체 발송 활성화, 수신 중단 기준, 반복 주기 표시.
- 최근 24시간 평균: 읽기 전용 값, 표본 수, 미측정 제외 수, 허용편차%에 따른 범위 미리보기. 부족하거나 오래된 평균은 기존 고정 범위로 대체.
- 모바일 설정: 전체 높이 모달, 고정 하단 저장 버튼, 사용 중 항목 우선 표시, 평균 사용 시 대체 고정 범위 접기.
- 수신처: 담당자 지정, 접근 가능한 전체/다중 병원 등록, 병원별 이름·전화번호 현황. 기존 수신처 담당자도 관리자에게 변경 허용.
- 일반 사용자: 접근 가능한 병원의 본인 수신처 조회·등록·수정·삭제만 허용. 회사/병원 접근 검사는 서버에서 수행.
- 조용한 시간: 해당 담당자 번호에 알림톡/SMS 모두 제외. 자정을 넘는 범위 지원. 사업장 전체 발송 제외 정책은 별도 적용.
- 이력: 진행 중 기본 보기, 상세 전송 결과 접기, 20건씩 페이지 표시. 복구 이벤트 생성·발송·목록 표시 제거.
- 반복: 기본 30분. 정책에서 0(최초 1회) 또는 5~10080분으로 설정 가능. 모니터링 실행 간격에 따라 실제 발송 시각이 늦어질 수 있음.
- 확인완료: 재확인 대화상자 이후 사용자별 확인 저장. 그 사용자의 사업장 수신 번호만 해당 사건에서 제외. 정상→재이탈 시 새 사건이므로 다시 발송. 정상 수신 전 미측정 값만 나온 경우 사건을 종료하지 않음.
- 새 승인 템플릿 `BB0836851023705085`: 바로빌 API는 코드가 아닌 템플릿명 `MRI 장비 상태 이상 감지 알림 - 간소화`로 지정. 승인 본문을 사용하고 장비명 URL 변수에는 site ID를 URL 인코딩해서 전달. SMS 대체 설정 유지.

## DB 변경 및 배포 주의

- V21: `alert_event_acknowledgement` 사건/사용자 복합키와 FK 추가. 기존 반복 주기 0을 30으로 변경.
- 기존 수신처의 사용자 ID는 자동 추정하지 않음. 기존 등록자가 관리자였던 번호는 수신처 수정에서 실제 담당자로 재지정해야 본인 확인완료/수신 설정이 정확하게 연결됨.
- 이전 작업 V17~V20도 아직 미커밋 변경에 포함되어 있음. 이번 작업에서 공유/운영 DB 변경, 커밋/푸시/배포, 실제 메시지 발송은 하지 않음.

## 검증

- Java 17 전체 백엔드 테스트: 76건 통과.
- 추가 회귀 테스트: 담당자별 번호 제외, 새 사건 재수신, 정상 범위 복귀 시 복구 발송 없음, 지속 이탈 방향 변경 시 사건 유지, 다른 사용자의 수신처 등록 차단.
- 프론트엔드 eslint, 타입 검사, production build 성공. git diff --check 통과.
- 이번 V21의 실제 DB 적용과 모바일 실기기 화면/수신 검증은 아직 수행하지 않음.
