## 운영 스키마 확인

공유 MRI DB에 읽기 전용 쿼리로 확인. 이번 배포에는 신규 DB 마이그레이션 없음.

- Flyway V1~V16 모두 성공.
- 활성 사용자 중 이메일 누락 0건.
- 존재하지 않는 병원에 연결된 `company_site`, `site_alert_recipient` 0건.
- 활성 수신처의 동일 사업장/채널/전화번호 중복 0건.
- `site.site`와 주요 연결 컬럼은 `VARCHAR(32)`, `utf8mb4_unicode_ci`로 일치. 병원 FK는 아직 없음.
- `mrtb` 약 29.6만 행, 데이터·인덱스 합계 약 41.6MB (information_schema 추정).

## 후속 작업 우선순위

1. **병원별 측정 이력 조회 인덱스**: `SiteService`의 `WHERE siteid=? ORDER BY date DESC, index DESC LIMIT ?` 실행계획이 `ix_mrtb_date_site`로 약 148,225행을 검토하는 계획을 선택. `(siteid,date,index)` 인덱스를 격리 DB에서 비교한 뒤 별도 마이그레이션으로 적용 검토. 실제 지연시간과 부하 개선치는 아직 측정하지 않음.
2. **알림톡 접수와 실제 도착 구분**: `MonitorService`는 바로빌 접수 성공 직후 `SENT`로 표시하고 반환 접수번호를 저장하지 않음. `alert_delivery_result`에 접수번호·최종 채널·최종 결과·확인시각을 저장하고 상태 조회를 연동하면 알림톡 도착 및 SMS 대체 결과까지 앱에서 확인 가능.
3. **병원 연결 무결성**: 주요 병원 연결 컬럼의 형식은 일치하므로 FK 도입 검토 가능. 회사 이관·병원 삭제 정책과 레거시 수집기를 먼저 검증하고 단계적으로 추가.
4. **측정값 정규화**: `mrtb` 측정값 11개가 `VARCHAR(10)`. 숫자 컬럼과 미측정 상태를 분리하는 신규 수집/조회 모델을 검토. 기존 0/0.01/0.001 제외 규칙과 레거시 수집기 호환을 유지하는 이행이 필요.
5. **이력 보존 정책**: 만료/폐기 세션 6건, 만료 재설정 토큰 1건 확인. 측정 원본·알림·감사 로그·세션·토큰의 보존 기간과 정리 작업을 정의. 현재 적체량은 작으므로 긴급 작업은 아님.

사용자 전화번호와 사업장 알림 수신처의 별도 관리는 기존 결정대로 유지한다. 새 간소화 알림톡 템플릿 승인 후에는 템플릿명/본문을 코드와 일치시키고 버튼 링크를 활성화한 다음 승인된 수신처로 도착 검증이 필요하다.
