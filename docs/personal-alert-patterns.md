# 개인 병원 알림 패턴

알림 기준과 발송 일정은 `(사용자, 병원)` 단위다. 관리자도 본인의 패턴을 설정하며, 다른 사람의 패턴을 직접 바꾸지 않는다. 수신처는 담당자·병원·휴대폰 번호를 연결한다.

- `/alerts/thresholds`, `/alerts/policy/{site}`, `/alerts/thresholds/{site}/metrics/{metric}`는 로그인한 사용자의 설정을 반환/저장한다. 회사 공통 기준 변경은 기존 관리자 제한을 유지하며 초기 패턴의 참고 기준이다.
- 평균 표본은 병원별로 공유하지만 평균 사용 여부·허용편차·수동 범위·수집 누락·콜드칠러·반복 주기·조용한 시간·주말/지정 휴일은 개인별로 적용한다.
- `alert_rule.user_id`와 `(user_id,site_id,metric_key,rule_type)` 고유 키로 발생·지속 상태·반복·확인을 분리한다. 수신자는 이 사건의 소유자에게 등록된 번호만 사용한다. 실제 발송 직전에 활성 계정/회사/병원 권한과 확인 여부를 검증한다.
- 대시보드 상태와 범위도 개인 설정/사건을 적용한다. 다른 사용자의 사건 ID로 확인·재전송·전송 결과 조회를 시도하면 찾을 수 없음으로 응답한다.
- 이전 공통 사건(user_id=0)은 이력에 남는다. 전환 시 상태 종료만 기록하며 사용자 확인을 자동으로 만들지 않는다. 공통 사건은 재전송할 수 없다.

## 공유

같은 회사이며 해당 병원에 접근할 수 있는 활성 사용자끼리 공유한다. USER → USER를 포함한다. 서버가 저장된 패턴의 사본을 `alert_pattern_share`에 기록한다. 수신 번호와 이력은 공유하지 않는다.

받은 사용자가 내용과 덮어쓰기 안내를 확인한 뒤 ‘내 설정으로 적용’을 누르면 자신의 병원 패턴에 복사한다. 원본이나 다른 담당자의 설정은 변경되지 않는다. 원본이 나중에 수정되어도 이미 공유한 사본/적용한 패턴은 변하지 않는다. 적용 시에도 현재 수신자 및 병원 권한을 재검증한다.

## 기존 설정 전환

각 활성 사용자의 접근 가능한 병원에 기존 기준과 정책을 최초 1회 사본으로 저장한다. 기존 담당자 수신처의 조용한 시간도 반영한다. 회사/병원 시간과 담당자 시간이 다르면 발송 제외 범위를 보수적으로 합친다(떨어진 구간은 작은 간격까지 제외). 전체 하루가 제외되거나 담당자의 수신처가 모두 중지돼 있었다면 개인 알림을 중지 상태로 시작한다. 수신처의 사용 여부는 이후 개인 패턴에서 관리한다.

기존 공통 설정 테이블은 초기 기준을 제공하기 위해 유지한다. 개인 설정 저장은 다른 사용자나 기존 공통 기준을 덮어쓰지 않는다. 같은 개인 패턴 변경은 트랜잭션과 행 잠금으로 직렬화한다. 조용한 시간 변경은 살아 있는 사건을 자동 종료/확인하지 않는다. 비활성화한 해당 개인 항목만 종료한다.

## 검증

Java 17 `./gradlew test`, 프런트엔드 ESLint/TypeScript/production build, 알림 상태 및 공개 인증 회귀 테스트를 실행한다.

`PersonalAlertDatabaseTest`는 별도 로컬 테스트 DB에서만 실행한다. 환경 변수 `PERSONAL_ALERT_TEST_DB_URL`은 `jdbc:mariadb://127.0.0.1:<port>/personal_alert_test`만 허용한다. 테스트 전용 스키마를 초기화하며 애플리케이션 DB에 접속하지 않는다. 로컬 MySQL 5.7에서 V30 SQL 적용, 일반 사용자/관리자의 사건 접근 분리, 공유 사본 및 적용, 기존 제외 시간·중지 상태·이력 보존을 검증했다. 운영 MariaDB 배포 시 Flyway와 헬스 체크도 확인한다.

실제 알림톡/문자 발송이나 실사용자 간 테스트 공유는 실행하지 않는다. 브라우저에서는 별도 로컬 fixture의 USER 계정으로 저장·공유·확인·적용 및 모바일 폭 390px에서 가로 넘침 없음을 확인했다.
